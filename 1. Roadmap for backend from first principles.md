# Backend Engineering Notes 🚀

> **Understanding backend systems from first principles — not just learning frameworks.**

These are my personal notes while learning **Backend Engineering**.

The goal isn't to memorize Express, Spring Boot, Django, Go, Node.js, or any other framework.

The goal is to understand **what is happening underneath the framework**.

Because frameworks change.

**Fundamentals don't.**

---

# 🧠 What is Backend Engineering?

Backend engineering is much more than building a bunch of CRUD APIs.

A good backend system should be:

* ⚡ Efficient
* 🔒 Secure
* 📈 Scalable
* 🛡️ Fault-tolerant
* 🔄 Reliable
* 🧹 Maintainable
* 👀 Observable

The interesting part is understanding **how all these pieces work together**.

For example:

```text
                    CLIENT
                       │
                       ▼
                    HTTPS
                       │
                       ▼
                 Load Balancer
                       │
                       ▼
                Backend Server
                       │
             ┌─────────┴─────────┐
             ▼                   ▼
           Cache              Database
             │
             ▼
           Queue
             │
             ▼
          Workers
```

And around the entire system:

```text
Security
Logging
Monitoring
Tracing
Testing
Configuration
Scaling
Deployment
```

This repository is my attempt to understand that entire picture.


# 06. Validation & Transformation ✅

Never trust incoming data.

```text

   │
   ▼

   │
   ▼
Transform
   │
   ▼
Normalize
   │
   ▼
Sanitize
   │
   ▼
```

### Validation Types

**Syntactic**

```text
Is this a valid email?

Is this a valid date?
```

**Semantic**

```text
Can date of birth be in the future?
Is the age within a valid range?
```

**Type**

```text
String?

Boolean?
Array?
Object?
```

### Transformation

For example:

```text

  ▼
```


* Lowercase emails

* Convert date formats
* Convert timestamps

### Complex Validation

```text
       ↓
```

Conditional validation:


# 09. Controllers, Services & Business Logic 🏗️

```text

   │
   ▼

   │
   ▼
Service
   │
   ▼
Data Access Layer
   │
   ▼

```

### Controller

Deals mainly with:

* Receiving requests
* Presentation concerns
* Calling services
* Returning responses

### Service

Deals mainly with:

* Business logic
* Business rules
* Application operations

### Data Access Layer

Deals mainly with:

* Queries
* Inserts
* Updates
* Deletes

### The goal

Keep controllers thin.

```text
❌ Controller

   ├── Business logic
   ├── SQL
   ├── Email
   └── Response

✅ Controller
   ↓
Service
   ↓
Repository / DAL
   ↓
Database
```

# 14. Caching ⚡

Databases are powerful, but repeatedly fetching the same data can be expensive.

Caching puts frequently used data closer to where it is needed.

```text
Client
  │
  ▼
Server
  │
  ▼
Cache
  │
  ├── HIT ──→ Return Data
  │
  └── MISS
        │
        ▼
     Database
        │
        ▼
    Store Cache
        │
        ▼
    Return Data
```

### Caching Strategies

* Cache-aside
* Read-through
* Write-through
* Write-back

### Eviction

* LRU
* LFU
* FIFO
* TTL

### Cache levels

```text
L1
Fast + Small
    ↓
L2
Slower + Larger
```

### Metrics

* Cache hit
* Cache miss
* Hit ratio
* Miss ratio

### The question

> **When should we trade freshness and complexity for speed?**

# 19. Graceful Shutdown & Security 🛑🔐

## Graceful Shutdown

A server shouldn't simply disappear while processing requests.

```text
Shutdown Signal
      ↓
Stop accepting new requests
      ↓
Finish in-flight requests
      ↓
Close database connections
      ↓
Close files / resources
      ↓
Terminate
```

### Signals

* SIGTERM
* SIGINT
* SIGQUIT

### Useful during

* Server restarts
* Cloud scaling
* Container shutdown
* Microservices
* Long-running jobs

---

## Backend Security

Security isn't a single feature.

It exists throughout the system.

### Common attacks

* SQL Injection
* NoSQL Injection
* XSS
* CSRF
* Broken authentication
* Insecure deserialization

### Security principles

**Least Privilege**

```text
Give only the permissions required.
```

**Defense in Depth**

```text
Security Layer
      ↓
Security Layer
      ↓
Security Layer
```

**Secure Defaults**

```text
Default configuration
        ↓
Should already be secure
```

**Security by Design**

Security should be considered from the beginning, not added at the end.

## Concurrency vs Parallelism

### Concurrency

Managing multiple tasks.

Useful for:

* Network requests
* Database queries
* File operations
* I/O-bound work

### Parallelism

Executing multiple tasks simultaneously.

Useful for:

* CPU-bound workloads

```text
Concurrency
→ Managing multiple tasks

Parallelism
→ Executing multiple tasks simultaneously
```
